# Apply HumanTouch in every session or project

`/human` runs only when you type it. To make the assistant apply the same rules whenever it writes text for you in a project, add the block below to that project's instructions file. For Claude Code, this is `CLAUDE.md` at the project root.

```markdown
## Writing style

When you write text for me (emails, posts, documents, messages, proposals), follow the rules in `skills/human/SKILL.md` from the HumanTouch repository:

- Write natural, human-sounding prose in the language and register of the context.
- Keep every fact, figure, name, date and claim. Keep the strength of any praise or judgment.
- Do not add filler openers, disclaimers, summaries, headings or transitions the content does not need.
- Keep the author's voice. Do not replace it with a generic friendly one.
- Do not add signatures, attribution or "generated by" marks to any text.
```

Replace the path with the location where you cloned the repository, for example `~/human-touch/skills/human/SKILL.md`.

## Notes

- The block applies to text the assistant writes for you during the session or project. It does not apply to code, code comments or commit messages, unless you ask.
- Rules that apply to every session belong in the user-level instructions. Rules that apply to one project belong in that project's instructions file.
- The assistant applies these rules as guidance. It does not guarantee that every rule is followed in every reply. Check important texts before you send them.
